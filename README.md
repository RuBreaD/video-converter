# Сервис обработки видео

Сервис принимает видео по HTTP и ставит его обработку в очередь. FFmpeg запускается в фоне, поэтому загрузка быстро возвращает `jobId`. Готовый файл можно скачать отдельным запросом.

Пошаговая инструкция для пользователя — в [GUIDE.md](GUIDE.md). В [TRACEABILITY.md](TRACEABILITY.md) собраны пункты ТЗ и соответствующие им части кода.

## Запуск

Нужны Go 1.25 или новее и FFmpeg с кодеком `libx264`. На macOS FFmpeg можно поставить через Homebrew, на Ubuntu или Debian — через apt:

```bash
brew install ffmpeg
```

```bash
sudo apt install ffmpeg
```

Проверьте, что FFmpeg установлен и видит `libx264`:

```bash
ffmpeg -version
ffmpeg -encoders | grep libx264
```

Из корня проекта запустите сервер:

```bash
go run .
```

Сервер слушает порт 8080. Swagger UI находится по адресу <http://localhost:8080/docs>, спецификация API — <http://localhost:8080/openapi.yaml>. Для самой страницы Swagger нужен интернет: её JavaScript и CSS загружаются с CDN. API работает локально.

## Быстрый пример

Загрузите видео. В multipart-запросе поле должно называться `file`:

```bash
curl -F 'file=@video.mp4' http://localhost:8080/videos
```

В ответе будет ID нового задания:

```json
{"jobId":"72b3fa31a24e4171b8556aa82fd01234","status":"queued"}
```

Проверьте его состояние:

```bash
curl http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234
```

Когда состояние станет `completed`, скачайте MP4:

```bash
curl -fL -o result.mp4 http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234/result
```

Чтобы отменить ожидающее или выполняющееся задание:

```bash
curl -X POST http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234/cancel
```

Один запрос загрузки принимает один файл. Чтобы поставить в очередь несколько видео, отправьте отдельный `POST /videos` для каждого.

## Файлы и преобразование

Принимаются файлы с расширениями `.mp4`, `.mov`, `.mkv`, `.webm` и `.avi`. При загрузке файл копируется на диск потоково; содержимое целиком в память не читается. По умолчанию размер ограничен 1 GiB. Расширение проверяется при загрузке, а формат и целостность файла — уже FFmpeg при обработке.

Результат всегда MP4: видео кодируется в H.264, звук — в AAC. Картинка уменьшается до 1280×720 с сохранением пропорций; маленькое видео не растягивается. Параметры FFmpeg задаёт сам сервис.

## Очередь и настройки

По умолчанию одновременно работают два FFmpeg, ещё двадцать заданий могут ждать. Если очередь заполнена, загрузка завершится ответом HTTP 503. Работающие задания в размер очереди не входят.

Настройки задаются переменными окружения:

| Переменная | По умолчанию | Для чего нужна |
| --- | --- | --- |
| `ADDR` | `:8080` | Адрес HTTP-сервера |
| `DATA_DIR` | `data` | Каталог с видео и `jobs.json` |
| `FFMPEG_PATH` | `ffmpeg` | Путь к FFmpeg, если его нет в `PATH` |
| `WORKERS` | `2` | Число одновременно обрабатываемых заданий |
| `QUEUE_SIZE` | `20` | Число ожидающих заданий |
| `MAX_UPLOAD_BYTES` | `1073741824` | Предельный размер одного файла в байтах |
| `JOB_TIMEOUT_SECONDS` | `600` | Максимальное время обработки одного видео |

Например, так можно запустить один worker, очередь на пять файлов и timeout в две минуты:

```bash
WORKERS=1 QUEUE_SIZE=5 JOB_TIMEOUT_SECONDS=120 go run .
```

## Состояния задания

```text
queued → processing → completed
   │         ├──────→ failed
   │         ├──────→ canceled
   │         └──────→ timed_out
   └────────────────→ canceled
```

Если FFmpeg не запускается или возвращает ошибку, задание получает статус `failed`; сообщение и код завершения доступны в `GET /jobs/{id}`. Если истёк timeout, процесс останавливается и состояние становится `timed_out`.

При отмене задания в очереди worker пропускает его, когда до него доходит очередь. При отмене уже запущенного FFmpeg API дождётся остановки процесса и удаления временного результата, после чего вернёт `canceled`. Повторно отменить завершённое задание нельзя: сервер ответит HTTP 409. Скачать результат можно только для `completed`.

FFmpeg пишет временный файл с суффиксом `.part.mp4`. После успешной обработки он переименовывается в итоговый файл. `stdout` отбрасывается, а для диагностики ошибки сохраняются последние 8 KiB `stderr`, поэтому большой вывод FFmpeg не заполняет память или pipe.

## Хранение и остановка

Состояния заданий хранятся в `DATA_DIR/jobs.json`, входные видео — в `DATA_DIR/inputs`, результаты — в `DATA_DIR/outputs`. Снимок метаданных записывается во временный файл и атомарно заменяет предыдущий. Запускайте только один экземпляр сервиса на один `DATA_DIR`.

После обычного перезапуска готовые задания и результаты остаются доступны. Если приложение перезапустилось во время обработки, задание станет `failed`, а незавершённый результат будет удалён. При `Ctrl+C`, `SIGINT` или `SIGTERM` сервер перестаёт принимать новые запросы, ждёт текущие запросы до 15 секунд и затем останавливает активные FFmpeg-процессы.

Приложение не удаляет старые задания и видео автоматически. Когда результаты больше не нужны, очистите `DATA_DIR` вручную. После аварийного убийства самого приложения сигналом `SIGKILL` FFmpeg может остаться в системе; остановить дочерний процесс в этом случае должен внешний supervisor.
