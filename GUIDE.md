# Как обработать видео

## Запустить сервис

Понадобятся Go 1.25+ и FFmpeg с кодеком `libx264`. Если FFmpeg ещё не установлен:

```bash
# macOS
brew install ffmpeg

# Ubuntu или Debian
sudo apt install ffmpeg
```

Убедитесь, что команды доступны:

```bash
go version
ffmpeg -version
ffmpeg -encoders | grep libx264
```

Из папки проекта запустите:

```bash
go run .
```

Сервер будет доступен на <http://localhost:8080>. Остановить его можно через `Ctrl+C`; сервис закроет HTTP-сервер и остановит запущенные им FFmpeg-процессы. Видео, результаты и список заданий по умолчанию сохраняются в папке `data/` рядом с проектом.

## Загрузить видео через Swagger

1. Откройте <http://localhost:8080/docs>.
2. Найдите `POST /videos` и нажмите **Try it out**.
3. Выберите файл в поле `file` и нажмите **Execute**.
4. Скопируйте `jobId` из ответа. Сервер ответит сразу, обработка продолжится в фоне.
5. Вызовите `GET /jobs/{id}` с этим ID. Когда статус станет `completed`, скачайте файл через `GET /jobs/{id}/result`.

Страница Swagger подгружает оформление с CDN, поэтому для неё нужен интернет. Если страница не открывается полностью, API можно использовать через `curl`.

## То же самое через curl

Загрузите файл. Путь после `@` замените на путь к своему видео:

```bash
curl -F 'file=@/путь/к/видео.mp4' http://localhost:8080/videos
```

Ответ содержит ID задания:

```json
{"jobId":"72b3fa31a24e4171b8556aa82fd01234","status":"queued"}
```

Подставьте его в команды проверки и скачивания:

```bash
curl http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234
curl -fL -o result.mp4 http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234/result
```

Если хотите отправить несколько видео, сделайте отдельный запрос для каждого файла. Например:

```bash
for file in video1.mp4 video2.mp4 video3.mp4; do
  curl -F "file=@$file" http://localhost:8080/videos
done
```

## Проверить статус или отменить

`GET /jobs/{id}` возвращает состояние задания. Возможны такие статусы:

| Статус | Что происходит |
| --- | --- |
| `queued` | Задание ждёт свободного worker |
| `processing` | FFmpeg обрабатывает видео |
| `completed` | Результат готов, его можно скачать |
| `failed` | FFmpeg не запустился или не смог обработать файл; подробность будет в `error` |
| `canceled` | Задание отменено пользователем или при остановке сервиса |
| `timed_out` | Истекло отведённое на обработку время |

Отмена выполняется запросом:

```bash
curl -X POST http://localhost:8080/jobs/72b3fa31a24e4171b8556aa82fd01234/cancel
```

Задание в очереди отменяется сразу. Если FFmpeg уже запущен, запрос дождётся остановки процесса и удаления временного файла. Завершённое задание отменить нельзя — сервер ответит HTTP 409. Результат также доступен только для задания со статусом `completed`.

## Ограничения и настройки

Поддерживаются расширения `.mp4`, `.mov`, `.mkv`, `.webm` и `.avi`. Файл преобразуется в MP4 с видео H.264 и звуком AAC; разрешение уменьшается максимум до 1280×720 с сохранением пропорций. Размер загрузки по умолчанию ограничен 1 GiB.

Обычно работают два FFmpeg-процесса, ещё двадцать заданий ждут в очереди. Если очередь заполнена, сервер вернёт HTTP 503; слишком большой файл отклоняется с HTTP 413. Настройки можно поменять при запуске:

```bash
WORKERS=1 QUEUE_SIZE=5 JOB_TIMEOUT_SECONDS=120 MAX_UPLOAD_BYTES=536870912 go run .
```

Полный список переменных окружения есть в [README.md](README.md). Исходники, результаты и метаданные не удаляются автоматически; когда они больше не нужны, очистите `DATA_DIR` вручную.

Спецификация API доступна по адресу <http://localhost:8080/openapi.yaml>. Ссылки на реализацию пунктов задания собраны в [TRACEABILITY.md](TRACEABILITY.md).

## Если что-то не получается

- `cannot start FFmpeg` — проверьте `ffmpeg -version` или задайте правильный `FFMPEG_PATH`.
- `failed` с ошибкой FFmpeg — посмотрите поле `error` в `GET /jobs/{id}`; файл может быть повреждён или содержать неподдерживаемый поток.
- HTTP 413 — файл больше `MAX_UPLOAD_BYTES`.
- HTTP 503 — очередь заполнена или сервис остановлен.
- HTTP 404 — проверьте ID задания и значение `DATA_DIR`.
